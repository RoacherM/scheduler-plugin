# ⏰ DSH 定时任务（@local/dsh-scheduler）

用自然语言创建按时间自动运行的 Agent 任务。**每次运行都在任务的工作区里新开一个会话**，Agent 带着完整工具（包括连接器，如 Gmail）无人值守地完成任务，结果记录在运行历史里。

## 用法
直接在对话里说：
- 「每个工作日早上 9 点检查我的 Gmail 新邮件，挑出需要我回复的并起草回复」
- 「每 2 小时看一下 GitHub 上新的 issue」
- 「明天下午 3 点提醒我给王总回邮件」

Agent 会把时间解析成规则（按你浏览器的时区）、把任务写成自包含的指令，调用 `scheduler_create` 后告诉你规则和接下来几次运行时间。

## 任务页
左侧栏「定时任务」页面只留最基础的控制：
- 开关、立即运行、删除、运行记录（可打开每次的会话）；
- **时间**：每天/每周/每月的任务可以直接改时刻，每周的任务还可以点选星期；间隔、一次性、cron 规则只显示文字；
- **模型**：跟随 DSH 默认，或固定用某个模型。

其余一切（新建、任务指令、连接器、工作区、思考强度、复杂的时间规则、错过时间的处理、权限）都在对话里完成：「新建任务」、示例短语和「在对话里修改」都会在任务的工作区里新开一个会话，Agent 先开口问你要做什么或改什么，再调用 `scheduler_create` / `scheduler_update`。

## 规则
`once`（一次）、`every`（固定间隔，≥1 分钟）、`daily`、`weekly`（ISO 星期，周一=1）、`monthly`（缺日期的月份跳过）、`cron`（标准 5 段）。都带 IANA 时区，跨夏令时保持本地时间不变。

## 运行语义
- 每次运行的首条消息包含：本次/计划时间、**上次成功运行时间**（便于「只看新邮件」）、所用连接器及其当前是否在线、「无人值守不要提问」的要求，然后是任务指令。聊天里显示为「定时任务」触发卡片。
- 先推进下次时间再启动运行，出错也不会重复触发；上一次还没结束则本次记为「跳过」。
- 电脑睡眠/应用关闭错过的时间合并为一次补跑；`misfire: skip` 则晚于 15 分钟的直接跳过。定时器至少每小时自检一次。
- 会话第一轮结束（`turn/end`）即记录结果：完成/失败/中止，附最后回复摘要。应用关闭时仍在运行的记为「中断」。一次性任务运行后自动停用。

## Agent 工具
`scheduler_create` · `scheduler_list` · `scheduler_update`（改名/改指令/改时间/暂停/恢复）· `scheduler_delete` · `scheduler_run_now` · `scheduler_runs`

## 数据
`~/.dsh/plugin-data/scheduler/tasks.json`（任务 + 每个任务最近 50 次运行）。运行会话是普通会话，删除任务不会删除它们。

## 开发
```sh
../pnpm-with-node install
node build.mjs     # dist/host.js（打包 croner）+ client.js
npm test           # 20 项：规则与夏令时、调度引擎（补跑/跳过/重叠/重启恢复）、模型回退、工具与路由、对话入口、jsdom UI、打包产物
```
和内置 `@deepseek-ai/dsh-schedule` 的区别：内置那个只把提醒投递回原会话；这个每次新开会话真正执行任务，并与连接器配合。
